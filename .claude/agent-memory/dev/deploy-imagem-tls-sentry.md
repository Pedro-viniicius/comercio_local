Conferido em 2026-10-16 (etapa 13 do 01a; @sentry/nestjs 11.7.0, Prisma 7.10.0, pnpm 12.4.1, node:22.23.3-trixie-slim):
- Sentry 11 NÃO tem `sendDefaultPii`: virou `dataCollection`, e sem ele o SDK coleta TUDO (userInfo/IP, cookies, cabeçalhos, corpos, query, dados de banco, variáveis locais). `sentry.ts` desliga cada categoria. `getDefaultIntegrations` devolve `Integration[] | undefined`. O ContextLines põe ±5 linhas de código-fonte no evento: em teste de vazamento, use constantes, não literais, perto do `captureException`.
- `@sentry/nestjs` não captura exceção que o nosso `FiltroDeErros` trata (o patch de `@Catch` só cria span). Por isso `InterceptadorDoSentry` (registrado no main com `new`).
- Release health (Q12, 2026-10-16): duas fontes de sessão no SDK 11 — integração `ProcessSession` (sessão do processo; `scope.setUser` atualiza o MESMO objeto em escopos clonados: `did` = id||email, `attrs.ip_address`) e `httpIntegration` com `sessions` (padrão true; agregados só com contagens). `client.sendSession` descarta se `release` for falsy. Sem `release` no init, o SDK deduz de `SENTRY_RELEASE`/`GITHUB_SHA`/~40 vars de CI (`sdk/api.js`); `release: ''` barra a dedução, mas o DSC (`trace` do cabeçalho) leva `"release":""` — removido no hook `createDsc`. Provar desligamento na origem: `client.on('beforeSendSession')`. `Integration`/`Envelope`/`Transport` não são reexportados pelo `@sentry/nestjs`: derive de `NodeOptions`. `setupOnce` do Http roda uma vez por processo (vale a 1ª opção). Sem `tracePropagationTargets`, o SDK põe `sentry-trace`/`baggage` em TODA requisição de saída (fetch e node:http, provado no teste HTTP real); `[]` desliga. O SDK lê do ambiente, se a opção for `undefined`: `SENTRY_SPOTLIGHT` (Spotlight posta cada envelope no `beforeEnvelope`, antes do transport, fora do `flush`: no teste, espere o sidecar com prazo), `SENTRY_DEBUG` (console fora do pino), `SENTRY_TRACES_SAMPLE_RATE` (sem opção que anule sem ligar spans: recusado no `ambiente.ts` em produção), `SENTRY_ENVIRONMENT`, `SENTRY_TRACE`/`SENTRY_BAGGAGE`. Fonte: `@sentry/node/build/cjs/sdk/index.js` e `utils/spotlight.js`. `flyctl` não está instalado na máquina: sintaxe de flag vem de docs.fly.io/flyctl/deploy.
- Script avulso que importa `src/` da API não roda com `node --experimental-transform-types` (decorators do Nest): use um `*.test.ts` temporário com vitest.
- Schema engine do Prisma (Rust) não conhece `sslmode=verify-full`: cai para `prefer` e aceita CA errada e nome errado (provado com Postgres TLS local; reconferido em 2026-10-19 com Prisma 7.10.1, engine d1b3f37). Equivalente: `sslmode=require&sslcert=<CA>&sslaccept=strict` (confere cadeia e nome: P1011 "unable to get local issuer certificate" / "hostname mismatch"). `require&sslcert` sem `sslaccept` também aceita CA errada. O `pg` entende o libpq (`verify-full&sslrootcert`). `urlDeMigracao` no prisma.config.ts traduz. A cada troca de `@prisma/engines-version`, refazer a sonda.
- Receita da sonda (reaproveitável): container `postgres:17.11-trixie` com `--entrypoint bash -c "cp /certs/x.crt /certs/x.key /tmp; chown postgres; chmod 600 key; exec docker-entrypoint.sh postgres -c ssl=on -c ssl_cert_file=... -c ssl_key_file=... -c log_connections=on"`, `-p 127.0.0.1:<porta>:5432`, init de `infra/postgres/init` montado, `--tmpfs` no data. Um segundo container com certificado de SAN `DNS:nao-confere.invalido` testa o nome. Para a URL crua, `prisma migrate deploy --config <config temporária no scratchpad>` com caminhos absolutos. O log `connection authorized ... SSL enabled` prova TLS. Node 22.23 importa `prisma.config.ts` direto (`node -e "import('./prisma.config.ts')"`).
- `pnpm deploy --prod` falha no postinstall `prisma generate` (prisma é dev): use `--ignore-scripts`. O CLI do Prisma vem no `.pnpm` como par de `@prisma/client`, sem link na raiz: o Dockerfile cria `node_modules/prisma` e `.bin/prisma`. O schema engine veio no deploy mesmo com `--ignore-scripts` (build limpo).
- `node --run <script>` (Node 22) põe `node_modules/.bin` no PATH: serve de `release_command` sem pnpm na imagem.
- Testar TLS do banco: Postgres 17 em container com `-c ssl=on`, certificados gerados com openssl no scratchpad, `--network host` e host `localhost` (SAN). Ver [[prisma7-banco]] e [[infra-local-docker]].
- Validar workflows sem instalar nada: `docker run --rm -v "$PWD:/repo:ro" -w /repo rhysd/actionlint:latest`; dependabot/workflows contra schema: `python:3.13-slim` + `pip install check-jsonschema` + `--builtin-schema vendor.dependabot`.
- SHAs de action: `git ls-remote --tags` (usar o `^{}` de tag anotada) e conferir com `api.github.com/repos/<r>/commits/<sha>` (data, para a regra de 3 dias).

**How to apply:** deploy, CI, Sentry nos apps/painel (01b) e qualquer conexão nova com o banco.
