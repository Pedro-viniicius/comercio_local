- Unitário de um arquivo da API: `pnpm --filter api exec vitest run <caminho>`. Integração: `pnpm --filter api test:integracao -- <trecho-do-nome>` (exige `docker compose -f infra/docker-compose.yml up -d --wait`; o globalSetup recria o banco de teste, então não rode contra dados que importem). Scripts da raiz: `node --test scripts/<arquivo>.test.mjs`.
- `pnpm test` na raiz para no primeiro pacote que falha (`pnpm -r` sem `--no-bail`): rode cada `pnpm --filter <pacote> test` e `node --test "scripts/**/*.test.mjs"` separados para ver tudo.
- Sonda fora do repo com decorators do Nest: vitest com `--config` no scratchpad (`root` no scratchpad, `include: ['*.sonda.test.ts']`, `resolve.conditions: ['@bairrin/fonte']`), `node_modules` do scratchpad como symlink para `apps/api/node_modules`, `tsconfig.json` local com `experimentalDecorators` e `emitDecoratorMetadata`, e `--disableConsoleIntercept` para ver `console.log`. tsx NÃO serve para código com decorators (sem metadados).
- Pacotes `@bairrin/*` resolvem por `dist/` fora do vitest da API; testes passam na máquina do dev só porque `dist/` existe. Cópia limpa: `git ls-files -co --exclude-standard | tar` para o scratchpad e `pnpm install --frozen-lockfile` (cria `/tmp/.pnpm-store`; apague depois). `scripts/instalacao-limpa.test.mjs` reproduz isso sem reinstalar.
- Imagem da API: `docker run --rm --network host -e NODE_ENV=development -e DATABASE_URL_MIGRACAO=<url teste 5433> <img> node --run migrar` valida o release_command (em produção exige verify-full).
- Provar que teste reprova no código antigo: cópia do repo no scratchpad (`git ls-files -co --exclude-standard | tar` sem `.claude/`), `node_modules` da raiz e de `apps/api` como symlink para os originais, depois `git show d6b2cbe:<arquivo>` por cima do arquivo de produção e `npx vitest run` dentro da cópia (o cliente Prisma gerado é gitignored: o teste "sem as fixtures" de fronteiras falha na cópia por isso, ignore). Funciona para `node --test scripts/...` também.
- Sonda contra o Postgres de teste sem o globalSetup: script `.mts` no scratchpad com `node --experimental-transform-types` (strip-only não aceita parameter properties), `createRequire` apontando para `apps/api/package.json` para achar o `pg`, e `postgres`/`dev_postgres_somente_local` em `127.0.0.1:5433/bairrin_teste` para criar schema de outro papel. Apague schemas e papéis (`anon`) criados no `finally`. `bairrin_migracao` não pode criar tabela temporária.
- `nestjs-pino` cria o pino-http uma vez por processo: só o primeiro `PinoLogger`/`Logger` de um arquivo de teste usa o destino em memória; os seguintes escrevem no do primeiro. Novos casos entram no mesmo `it`. pino-http sem rede: `new IncomingMessage(new Socket())`, `new ServerResponse(req)`, `emit('finish')`. Import é `{ pinoHttp }` (o default não tem call signature no NodeNext).
- Mutação de código de produção sem tocar o repo: cópia do repo no scratchpad (`git ls-files -co --exclude-standard | grep -v '^.claude/' | tar`), symlink de `node_modules` (raiz e `apps/api`) e de `dist/` e `node_modules` de `packages/{contratos,cliente-api,tokens}`; edite o arquivo na cópia e rode `npx vitest run --config vitest.integracao.config.ts migracoes --reporter=json --outputFile=<json>` (o stdout do reporter json vem misturado; use `--outputFile`). Cuidado: mutante que deixa `$3` sem uso quebra o SQL todo (falso 'reprova tudo'); `String.replace` troca só a 1ª ocorrência.
- `prettier --write` no repo foi negado pelo classificador do harness: use `prettier <arquivo> | diff <arquivo> -` e aplique à mão.
- Sentry (`@sentry/nestjs` 11.7): o SDK deriva `release` de `SENTRY_RELEASE` ou `GITHUB_SHA` (e vars de outros CIs) e, com release, abre sessão de release health e manda envelope `{"type":"session"}` ANTES do evento. Esse envelope não passa pelo `beforeSend` e leva `did` (id, ou e-mail se não houver id) e `attrs.ip_address` do usuário do escopo. Por isso `sentry.test.ts` falhou só no CI (GITHUB_SHA existe lá). Reproduz local com `GITHUB_SHA=abc pnpm --filter api exec vitest run <arquivo>`; nos testes use `vi.stubEnv('SENTRY_RELEASE', ...)`. Envelopes: cabeçalho + pares (item, carga) em linhas JSON. `Scope` não tem `clear()` na 11.7, e `setSession()` no escopo depois do init apaga a sessão que se quer testar. A sessão de um teste vaza para o seguinte no mesmo processo (escopo de isolamento padrão).
- Armadilhas do grupo A do 01b (2026-10-16): `pnpm exec`/`pnpm --filter` reinstala (~1 s, "added 625") antes de rodar; é normal. `packages/contratos` não tem `@types/node`: teste que lê arquivo (`node:fs`) vai para `apps/api/test/` (lint `no-unsafe-*` reprova no pacote). O lint de texto do log vale também para os `*.test.ts` de `apps/api/src`: monte template string numa variável antes de `logger.x(...)`. `prettier --write` negado: `prettier arq > scratchpad/fmt.tmp && cat fmt.tmp > arq` funciona. Mutação de validadores/contratos: script Python na cópia (troca 1 trecho, `vitest --reporter=json --outputFile`); mutante que remove um import usado dá "sobreviveu" falso (suíte nem carrega, sem assertionResults). Fixture `scripts/fixtures/migracoes/identidade-modelo/` é lida pelo verificador e pelo catálogo (int test): a migração real da etapa 3 deve seguir o mesmo formato (REVOKE FROM PUBLIC antes de GRANT em função e tipo).
- Mutação em lote (2026-10-16): script Python na cópia do scratchpad troca 1 trecho por vez, roda `npx vitest run ... --reporter=json --outputFile=<json>` e restaura. A integração compartilha o banco de teste (o globalSetup recria): rode os mutantes em sequência, nunca em paralelo, e não rode a suíte real ao mesmo tempo. Sonda de função pura do contratos: `node --experimental-transform-types x.mts` importando o `.ts` direto.
